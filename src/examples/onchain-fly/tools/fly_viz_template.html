How the fly controls the pool

1. Traders swap; the first swap in a new 25-block window closes the previous one: buy/sell volume, TWAP, fee income, LP loss and the closing spot are frozen (window).

2. A keeper submits decide(prevState) to the Gas Killer router. The router and three operators each trace the call under the unbounded profile: rasterize the closed window, run the whole fly brain for the episode, decode DNp20 / DNpe017 into fee and skew.

3. They sign the identical diff; the quorum-signed verifyAndUpdate writes ONE word into FlyPolicy (decision). The pool never receives a transaction from the fly.

4. Every swap reads that word with one SLOAD (effectiveFee), clamps it to 5–100 bps and the 2-window staleness limit, and charges it — the feeBps column below is what each trade actually paid.
